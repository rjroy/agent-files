## Project role routing

Use the repository's descriptions under **Project-specific routing guidance** as the authoritative specialist map; they refine or supersede the generic agent summaries above. In particular, @fixer is a general technical builder, not limited to trivial/mechanical edits; @oracle may implement substantial technical fixes, while a review invocation remains read-only under its selected procedure; and @explorer includes research beyond code search. @designer owns visual/UI design judgment, but is not the only agent permitted to produce visual artifacts: @creator can make direct creative outputs and @craftsman can refine complex artifacts. Route modeling according to whether visual direction or sustained creative refinement is central.

Keep the standard planning, delegation, background-task, messaging, session-reuse, escalation, and verification rules intact.

For procedure-driven work, select the retained agent whose capabilities fit the procedure's task role and obey its read/write and approval boundaries; agent identity does not change the procedure contract. Task skills own task workflows. Do not copy those workflows into routing or identity prompts. Existing user approval, asset-generation, installation, and integration gates remain in force.
